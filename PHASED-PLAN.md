## Phase 1: Hypothesis Validation (Weeks 1-2)

**Goal:** Prove that domain structure → deterministic test derivation (C2, RQ1)

**Experiments:** E1-E5

### E1: Derivation Determinism
- **Protocol:** Run test derivation on poker-team feature 3× with identical inputs; measure % of identical test outputs
- **Success Criteria:** ≥95% test identity (determinism confirmed)
- **Schedule:** Week 1

### E2: Derived vs Manual Coverage
- **Protocol:** Compare derived tests (from DomainSpec) vs manually authored tests on same feature
- **Success Criteria:** Derived coverage ≥ manual coverage
- **Schedule:** Week 1

### E3: Mutation Testing Effectiveness
- **Protocol:** Run Stryker on derived tests; measure mutation kill rate
- **Success Criteria:** Kill rate ≥85%
- **Schedule:** Week 2

### E4: Governance Attenuation (Foundation)
- **Protocol:** Measure agent compliance rate per layer (L3→L7); plot attenuation curve
- **Success Criteria:** Curve measured; baseline established for later interventions
- **Schedule:** Week 2

### E5: Observer-Executor Separation (Foundation)
- **Protocol:** Deploy observer agent + executor agent separately vs monolithic; measure fidelity before/after
- **Success Criteria:** Separation improves fidelity
- **Schedule:** Week 2

**Phase 1 Gate:**
- [ ] All E1-E5 JSONL files generated & validated
- [ ] All 5 success criteria: 5/5 PASS
- [ ] Research analyst reports: C2 strongly supported (or revision proposed)

## Phase 4: Agent Role Definitions (Weeks 8-9)

**Goal:** Define formal agent role contracts; identify role responsibilities in poker-team (C1, RQ3)

**Not running experiments.** Specification & audit phase.

### Deliverables

1. **Role Interface Specifications** (4 files in `implementation/roles/`)
   - `po-agent.md` — Product Owner agent contract
   - `qa-agent.md` — QA/Tester agent contract
   - `dev-agent.md` — Developer/Implementation agent contract
   - `stakeholder-agent.md` — Stakeholder/Vision agent contract

   **Template per role:**
   ```markdown
   # [Role] Agent Contract
   
   ## Responsibilities
   - [Primary decision domain]
   - [Information sources]
   - [Key outputs]
   
   ## Contract Interface
   ```
   interface [Role]Agent {
     inputs: {...},
     outputs: {...},
     sla: {latency_ms, token_budget}
   }
   ```
   
   ## Success Criteria
   - Decision quality metric
   - Consensus with other roles
   - Cost efficiency
   
   ## Communication Protocol
   - How does this role propose ideas?
   - How does it negotiate with peer roles?
   - How does it accept/reject peer proposals?
   ```

2. **Poker-Team Feature Audit** (1 document: `Phase4-Role-Audit.md`)
   - Map each poker-team feature to role touchpoints
   - Example: "auth-access-control feature"
     - PO: "What are the role hierarchies we need?"
     - QA: "What are the permission denial scenarios?"
     - Dev: "How does this integrate with our identity service?"
     - Stakeholder: "How does this support our growth strategy?"

3. **Role Disagreement Protocol** (1 document: `role-negotiation.md`)
   - When PO proposes feature X but QA says it's high-risk, how is conflict resolved?
   - What's the decision authority? (PO? Stakeholder? Vote?)

### Schedule
- Week 8: Draft role contracts (4 files)
- Week 9: Audit poker-team features, finalize role defs, get stakeholder sign-off

**Phase 4 Gate:**
- [ ] All 4 role contracts documented and approved
- [ ] Poker-team feature audit completed (all 7 features mapped)
- [ ] Disagreement protocol finalized
- [ ] **Approval:** Proceed to Phase 5 (feature discovery)

## Phase 7: Optimization & Specialization (Weeks 15-16)

**Goal:** Remove human-in-the-loop; enable agents to self-resolve conflicts; optimize roles based on performance (CM3, E14)

**Experiment:** E14 (Agent Specialization Under Pressure), E17 (Cost Attribution)

### Deliverables

1. **Conflict Auto-Resolution** (`auto-resolution-logic.md`)
   - When PO proposes and QA objects, agents debate using GOVERNANCE-SIGNALS (M-007–M-009) to reach consensus
   - No human decision needed

2. **Role Specialization Tuning** (based on E14 + E17 data)
   - If QA agent is consistently overbudget (tokens), reduce its scope
   - If Dev agent reaches consensus 95% of the time, increase its decision authority
   - If PO agent's proposals lead to quality regressions, increase skepticism

3. **5 Features Fully Autonomous** (No human review)
   - Run 5 features end-to-end without human intervention
   - Agents must resolve their own conflicts
   - Produced artifacts: stories, tests, tasks, metrics
   - Deploy features to staging

4. **Cost Optimization Report** (E17 output)
   - Token attribution per role (M-011)
   - Cost per feature (M-010)
   - Identify & optimize expensive roles

### Schedule
- Week 15: Implement auto-resolution, role specialization tuning logic
- Week 16: Run 5 features autonomous; collect cost data (E14, E17)

**Phase 7 Gate:**
- [ ] 5 features delivered fully autonomous
- [ ] Conflict auto-resolution working (≥90% no-human cases)
- [ ] Agent role specialization tuned (M-011 optimized)
- [ ] E14 + E17 data collected
- [ ] **Approval:** Proceed to Phase 8 (meta-governance)

## Risk Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Agent role conflicts unresolvable | Medium | High | Design disagreement protocol early (Phase 4); test on pilot (Phase 5) |
| Human-agent alignment <80% | Medium | High | Collect M-009 data early (Phase 2); iterate roles before Phase 6 |
| Attenuation curve not inverted | Medium | High | Run E4-E5 in Phase 1; if attenuation worsens, redesign L3-L6 governance |
| Cost per feature too high (>150k tokens) | Low | Medium | Track M-010 in Phase 2; optimize roles in Phase 7 |
| Agent specialization causes brittleness | Low | Medium | Test specialization on simple features first; keep role contracts stable |
