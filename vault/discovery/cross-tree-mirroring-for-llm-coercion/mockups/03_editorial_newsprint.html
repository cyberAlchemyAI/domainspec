The Three-Sibling Plan

A structural prescription for repos that wish to force LLM agents to write the right code — by making the path from any code edit to its governing spec mechanically computable.
— Filed from the Vault · Status: Exploratory · Pilot: maestro-trama

For years the framework asked a single engineering question: can I force the model to write the right code? The category theory came later, as the apparatus to make "right" checkable. Last week the question came back in a sharp form. An agent editing apps/labeling-platform/features/extraction/SPEC.md invented the path ../../../../docs/features/... — a path that does not exist. Across the repo, fifty-plus broken cross-references of the same shape were waiting to be found.

The failure is not aesthetic. It is the same failure mode the framework exists to prevent, performed on the framework's own substrate. A repository whose own structure cannot guide a careful agent has no business demanding the agent be careful.

This discovery proposes a structural fix: three top-level siblings, with the two structured siblings sharing a feature grammar so any path on one side maps mechanically to the other.

The Three Siblings

/research
Residue · sibling, not peer

Pre-structural work that has not yet earned an (app, feature) identity. Sessions, robot-talks, lenses-in-progress, ideas without a home. Forcing it into the structured grammar would invent identity rather than earn it.

/domain_knowledge
L₁ · structured

Specs, discoveries, invariants. Structured under apps/X/features/Y/{…}. Every artifact has a known identity.

/implementation
L₂ · mirrored

Code, tests, ops. Mirrored under the same grammar. The mirror is the precondition for a computable spec lookup.

"Structure provides the signal. The validator provides the enforcement. The coercion of the LLM is the long-term hypothesis this enables."

Promotion

residue → L₁

Necessary: earned (app, feature) identity — the author can name them without inventing them.
Sufficient: manual greenlight from the operator.

Partial identity (knows the app, not the feature) files under features/_unknown/ and promotes by frontmatter edit. Other signals — stability, citation, confidence — are observational, not gates.

Compilation

L₁ → L₂

Gate: the path-coherence validator (generalizing the vault's layer: field). Every L₂ feature must have an L₁ counterpart; every L₁ feature must declare its implementations or carry spec-only.

Plus: downstream test-derivability. If tests cannot be derived deterministically from the spec, the spec is underspecified and compilation is blocked. T0' is the long-term aspiration.

From the Pilot

Maestro-trama is the test bed. Its current state is the discovery's worked example: four proposal-orphans, four app-orphans, the extraction/ name collision created in a single commit on 2026-05-16 with no arbitration, and the fifty-plus broken cross-references discovered while patching that very file.

The migration is costed at twenty to thirty hours — roughly two times the prior folder-structure-fractal vault migration. Most of it is link rewriting; the rest is the unresolved business-philosopher/ question and the extraction/ arbitration that should have happened a week ago.

50+ broken cross-links 4+4 orphans (proposals + apps) 2 drifting extraction/ specs 20–30h pilot migration estimate

What This Is Not

This discovery does not claim that structure forces LLM correctness. That stronger claim — the one that would justify the whole apparatus — is parked behind a measurement plan we do not yet have. The validator delivers enforcement; whether enforcement plus structural symmetry actually reduces the agent error rate is an empirical question.

Until that measurement lands, the discovery is a navigation aid with a coercion hypothesis behind it, not a coercion result. The adversarial review forced this honesty: the prior folder-structure-fractal work was diminished by undefended theoretical claims, and we have no interest in repeating that error.
