NAME

     cross-tree-mirroring — three-sibling repo structure for L1<->L2 symmetry,
     a precondition for forcing LLM agents to write the right code.

SYNOPSIS

     repo/
     ├── /research           # residue holding pen  (sibling, not peer)
     ├── /domain_knowledge   # L1  (structured)     apps/X/features/Y/...
     └── /implementation     # L2  (mirrored)       apps/X/features/Y/...

DESCRIPTION

     The originating question of DomainSpec is engineering: can I force
     LLMs to write the right code?  The functor formalism came later as
     the apparatus to make "right" checkable.

     Today's repos make neither cheap.  An agent editing
     apps/labeling-platform/features/extraction/SPEC.md has no
     deterministic way to locate the L1 spec it must be faithful to.
     Last week's patch invented ../../../../docs/features/... — a path
     that does not exist (actual: docs/proposals/.../features/...).
     50+ broken cross-links of that pattern exist across
     apps/labeling-platform/features/.

     This discovery proposes a structural fix: three top-level siblings,
     with the two structured siblings sharing a feature grammar so any
     path on one side maps mechanically to the other.

SIBLINGS

     /research            Pre-structural work without earned (app, feature)
                          identity.  Filed freely.  Sibling, not peer:
                          theorem admits only 2 horizontal layers.

     /domain_knowledge    L1.  apps/X/features/Y/{...}  Specs, invariants,
                          domain models.  Every artifact has known identity.

     /implementation      L2.  apps/X/features/Y/{...}  Code, tests, ops.
                          Mirrors L1 grammar exactly.

MIRROR GRAMMAR

     /domain_knowledge                           /implementation
     └── apps/                                   └── apps/
         └── labeling-platform/                      └── labeling-platform/
             └── features/                               └── features/
                 └── extraction/                             └── extraction/
                     ├── SPEC.md         ←─Δ─→          ├── src/
                     ├── domain.md                       ├── tests/
                     └── operations.md                   └── ops/

OPERATIONS

promotion(residue → L1)
     necessary:  earned (app, feature) identity
     sufficient: manual greenlight
     partial:    file under features/_unknown/

compilation(L1 → L2)
     gate:       structural-completeness validator
     plus:       test-derivability check
     deferred:   T0' Lean obligations (long-term)

VALIDATOR

     Generalizes the vault's layer: path-coherence pattern to cross-tree.

     [OK]     implementation/apps/X/features/Y/ has counterpart in
              domain_knowledge/apps/X/features/Y/

     [FAIL]   implementation/apps/labeling-platform/features/extraction/
              has no L1 counterpart — orphan, blocked at pre-commit

     [WARN]   docs/proposals/ad-creative-dna/features/extraction/SPEC.md
              and apps/labeling-platform/features/extraction/SPEC.md
              both exist — name collision, requires arbitration
