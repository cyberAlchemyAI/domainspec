## M3 — Replace "Anti-dashboard discipline" + "Psychometric guardrails" sections with explicit imports

**Rationale.** The current sections at v0.4.0 lines ~417–494 carry prose lists ("prohibited uses", "allowed uses", "anti-patterns", "product-entry test") that re-derive what [`two-layer-retrieval#C-12`](../../two-layer-retrieval/discovery.md) (`DefectResidue`) and [`#C-14`](../../two-layer-retrieval/discovery.md) (`CalibrationFinding`) already specify as typed objects with explicit attributes. **Replacement.** Replace both sections with two import sections plus a re-framed H-11 (moved to Governance Gates per M4).

### Replaces "Anti-dashboard discipline" — Import: `DefectResidue` as the calibration output type

Adopt `DefectResidue` from [`two-layer-retrieval#C-12`](../../two-layer-retrieval/discovery.md) as the typed product object that replaces "anti-dashboard prose discipline." A `DefectResidue` instance is the system's typed statement that a required semantic structure was missing, collapsed, stale, contradictory, or untrusted. Applied to the head/spec/system triangle, every divergence that the calibration system surfaces is a `DefectResidue` with one of the following defect kinds:

- `missing-edge` — a `C_spec` rule has no `C_system` witness, or vice versa
- `stale-reference` — the reference surface has not been re-anchored in the relevant `task_family` within its freshness window
- `unresolved-symbol` — a `C_head` answer mentions a concept not present in `C_spec`
- `contradiction` — two `C_spec` subcategories disagree, or `C_head` answer contradicts `C_system` observed behavior
- `unsupported-claim` — a `C_head` answer asserts a rule not derivable from any `C_spec` node
- `code-doc-drift` — `d(spec, system)` exceeds a per-task-family threshold
- `runtime-doc-drift` — runtime substrate disagrees with `C_spec`
- `unsafe-retrieved-context` — the calibration query crossed a trust boundary

The Lean-layer authorization for this object is [`DefectResidue.lean`](/Users/victorboscaro/domainspec-theorem/lean-formalization/DefectResidue.lean) (sorry-free, see [FRAMEWORK-IMPLICATIONS.md §"Horizontal axis — What's closed"](/Users/victorboscaro/domainspec-theorem/FRAMEWORK-IMPLICATIONS.md)): noise is empty exactly at zero defect. The retrieval-layer adaptation is `two-layer-retrieval#C-12`.

### Replaces "Psychometric guardrails" — Import: `CalibrationFinding` as the typed observation record

Adopt `CalibrationFinding` from [`two-layer-retrieval#C-14`](../../two-layer-retrieval/discovery.md) as the typed product object that replaces the prose `prohibited uses` / `allowed uses` / `anti-patterns` / `product-entry test` lists at v0.4.0 lines ~434–494. A `CalibrationFinding` is *actionable maintenance residue with evidence, severity, owner hint, suggested action, age/recurrence, confidence, and status*.

The v0.4.0 lists become **attributes** of a `CalibrationFinding` instance, not standalone prose. C-14's `CalibrationFinding` (per the authoritative attribute list in [`two-layer-retrieval#C-16`](../../two-layer-retrieval/discovery.md), which defines the object boundary) carries exactly these fields verbatim: `evidence`, `severity`, `owner_hint`, `suggested_action`, `age`, `recurrence`, `confidence`, `status`. Everything else this discovery wants is a **novel extension on top of that import**, not part of the import itself. The two blocks below separate the two.

### How `RetrievalTrace` applies to the evidence-design matrix (v0.4.0 line 379)

The v0.4.0 evidence-design matrix at line ~381 has columns `C_head component | Task / elicitation | Observable | Intended inference | Threats | Confidence`. This is an under-typed precursor to `RetrievalTrace` from [`two-layer-retrieval#C-16`](../../two-layer-retrieval/discovery.md). Replace the matrix with a `RetrievalTrace` analog:

```yaml
# CalibrationTrace — adapted from two-layer-retrieval RetrievalTrace
calibration_trace:
  query: {head_component, task_family, reference_anchor}
  required_structure: {which_spec_nodes, which_system_observables, trust_floor}
  elicitation_actions: [list of probes issued, with kind: direct | inferred]
  selected_evidence: [SemanticAtom refs to C_head answers, C_spec nodes, C_system observations]
  rejected_evidence: [refs + rejection_reason]
  preserved_relations: [typed edges among the selected atoms]
  defects: [DefectResidue list]
  fallback_decisions: [e.g. degraded to declared-only because inferred-channel budget exhausted]
  stop_criteria: {evidence_target_met | budget_exhausted | structural_void}
  emitted_findings: [CalibrationFinding refs]
```

Every divergence claim the discovery makes at product layer must carry a `CalibrationTrace`. This subsumes the v0.4.0 "Threats" and "Confidence" columns as `rejected_evidence` and `evidence_envelope.confidence` respectively, and adds the missing audit dimensions (preserved relations, stop criteria, emitted findings).
