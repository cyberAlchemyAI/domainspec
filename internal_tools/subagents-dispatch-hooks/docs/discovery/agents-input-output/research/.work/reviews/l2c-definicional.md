# Review L2c — gate solidez definicional (colapso em conceito já nomeado)

**Alvo:** `.work/drafts/draft-v2.md` · **Réguas:** constituição v0.5.2 (§4 Princípios, §5 Parameter reference), `.claude/skills/research/SKILL.md`, descrição do agente `domainspec-research-writer` · **Dispatch:** 2026-06-12-agent-io-contracts

**Método:** para cada elemento de contrato da matriz §2 e da tabela de edges §4, perguntei: existe um conceito JÁ NOMEADO (princípio, campo §5, regra do type skill, contrato de agente existente) que este elemento re-apresenta sob nome novo? Três categorias: **colapso total** (já é lei — o elemento não pode entrar como candidato GO; só pode ser referenciado), **refinamento genuíno** (acrescenta algo, mas deve apontar para o conceito existente e nomear o delta), **novo real**. Distinção operacional: se apagar o elemento do draft não muda nenhuma obrigação (porque a obrigação já existe em outro lugar), é colapso total.

## Achados

**D1 — Header de fronteira por agente. Conceito existente: per-child headers do `domainspec-research-writer`. Natureza: REFINAMENTO sem ponteiro interno.**
A matriz (linha 1) cita só precedente externo (E2 §MetaGPT, §LangGraph) e forçamento P9+P5. Mas o repo JÁ tem um agente cujo contrato declarado é exatamente isso: `domainspec-research-writer` — "Mechanical assembly under per-child headers — no synthesis, no editing of child output". O header por filho não é proposta deste dispatch; é prática nomeada com dono. O delta genuíno do draft é o **conteúdo tipado** do header (`## E<n> — <nome> (<ângulo>, <modelo>)`) — os per-child headers existentes não fixam campos. *Correção:* a linha deve citar o research-writer como conceito existente e declarar o delta como "tipagem dos campos do header existente", não apresentar o header em si como elemento adotado. Verdict GO sobrevive; a coluna sound? está incompleta.

**D2 — Envelope tipado (frontmatter/headers) sobre corpo livre. Conceito existente: `initial_prompt` §5 ("the return expected"). Natureza: REFINAMENTO com ponteiro presente em §4 mas ausente em §2.**
§5 `initial_prompt` já define que o briefing contém "the return expected" — o canal pelo qual qualquer envelope é declarado JÁ existe e tem nome; era o que `expected_output_shape` teria sido antes de ser cortado. O edge parent→explorer (§4 linha 1) trata isso corretamente: "este edge é propriedade da constituição §5 — a tabela o referencia, não o re-decide". Mas a linha da matriz §2 ("Envelope tipado") não faz a mesma ancoragem: apresenta o envelope como elemento próprio sustentado só por E2/E1. O delta real é o lado do OUTPUT (o que o return deve conter), que §5 não fixa — esse delta é legítimo. *Correção:* a linha §2 deve abrir com "canal de declaração = `initial_prompt` (§5); este elemento fixa o CONTEÚDO declarado, não cria superfície nova de contrato". Sem isso, um leitor futuro pode reintroduzir um campo estruturado de input para carregar o envelope — exatamente o que a linha "Input por role" mata.

**D3 — Invariantes de condensação declarados. Conceito existente: exigência verbatim (skill §Outputs "collected returns, verbatim"; P9). Natureza: REFINAMENTO que afrouxa lei existente sem se declarar como emenda.**
O draft defende "não colapsa — é a cláusula de degradação do verbatim, não substituto". Aceito que não é re-skin. Mas há um problema definicional mais fino: **verbatim já é lei sem cláusula de exceção**. A testemunha (E1 evidência 3: verbatim degradou em dois passos) testemunha uma VIOLAÇÃO da lei, não uma lacuna nela. Ao instituir "se orçamento forçar condensação: IDs, severidades, âncoras, Dissent e posições são invariantes", o draft cria uma rota sancionada de não-verbatim que hoje não existe — afrouxamento de lei vestido de elemento de contrato. Pode ser a decisão certa (orçamentos são reais), mas então é uma **emenda declarada à regra verbatim do skill/P9**, com a violação observada como motivação — não um elemento novo de contrato. A alternativa coerente com a lei atual seria: condensação proibida; overflow → re-ask com token_budget revisado (o draft já usa re-ask para envelope malformado em §4). *Correção:* reclassificar como proposta de emenda à regra verbatim, com as duas formas (cláusula de degradação vs re-ask) explícitas; ou adotar re-ask e matar o ramo condensação.

**D4 — Pares posição-inicial/posição-final por reviewer. Conceito existente: P14, literal. Natureza: COLAPSO TOTAL — já é lei.**
P14: "the synthesizer MUST receive each review agent's **initial** and **final** position (both present in `working_folder`)". Isso é o elemento inteiro, incluindo a persistência. A própria matriz admite ("forçado literal por P14") e a coluna witnessed? admite "adjacente — a ausência dos pares em si não foi testemunhada". Apagar a linha do draft não remove nenhuma obrigação: P14 continua mandando exatamente o mesmo. Um verdict **GO** aqui infla a contagem de elementos adotados com lei pré-existente — é propor lei existente como novidade, ainda que com citação. O que o draft genuinamente ACRESCENTA está em outro lugar: (a) a localização dos pares no return do reviewer (P14 diz "present in working_folder", não diz onde); (b) o item (iv) do checklist do approver (verificação de P14 no close). *Correção:* trocar o verdict de GO para uma categoria distinta — "LEI EXISTENTE (P14): referenciada, não adotada" — e mover os deltas (a)/(b) para as linhas que os possuem (output do reviewer; checklist). A matriz de vereditos do skill é para CANDIDATOS; lei vigente não é candidato.

**D5 — Checklist de 6 itens do approver. Conceito existente: P12+P9 compostos (mais R5 do skill e P14). Natureza: REFINAMENTO correto no frame, com 4/6 itens sendo lei re-enumerada sem rótulo de fonte.**
A Colisão 1 resolve bem o colapso de superfície ("alojada onde já mora constitucionalmente — o final_approver, P12/R7") — a demoção é exatamente o movimento que este gate exige. Mas o checklist mistura status sem marcar: (i) = P9 literal; (ii) = skill §Tension design literal (Dissent em todo return) — e o consumidor já nomeado é o red-flag de falso-consenso do próprio skill; (iv) = P14 literal; (v) = operacionalização de P9 (citar transcript ≠ citar return coletado, pois o return coletado mora em research.md por definição de P9). Só (iii) draft persistido e (vi) tier são obrigações NOVAS. Apresentado como "checklist de 6 itens", parece seis aquisições; são duas aquisições + quatro enumerações de lei vigente. *Correção:* anotar cada item com sua fonte (P9 / skill-R5 / P14 / **novo**). Isso também protege o checklist do destino `success_metric`: itens com lei-fonte têm consumidor; os dois novos precisam do acoplamento que o draft já fez para (vi) — e (iii) deve apontar para D8.

**D6 — Linha `Dissent:` persistida no artefato durável. Conceito existente: skill §Tension design (Dissent mandatória) ∘ regra verbatim (P9/skill). Natureza: COLAPSO TOTAL por composição.**
O draft aponta a primeira metade ("exigência literal do SKILL") mas trata a persistência como acréscimo seu. Não é: se todo return de explorer/skeptic termina em `Dissent:` (lei do skill) E os returns coletados são verbatim em research.md (lei do skill/P9), então a Dissent persistida é **teorema das duas leis compostas**, não cláusula nova. O que os dois dispatches testemunham é violação das leis (emissão ou condensação — E1 evidência 4, indecidível), não lacuna definicional. O conteúdo genuíno do draft aqui se reduz a: (a) estender a obrigação a reviewers explicitamente (o skill diz "explorer/skeptic return" — reviewers SÃO skeptics no chassis, então nem isso é novo); (b) o item (ii) do checklist, que é verificação, não definição. *Correção:* mesma cirurgia de D4 — reclassificar como "LEI EXISTENTE (composição skill-R5 ∘ verbatim): referenciada"; o contrato só carrega o check de coleta que a torna verificável. Nota: D3 e D6 interagem — se a cláusula de condensação de D3 entrar, a derivação por composição quebra e a persistência da Dissent precisa virar invariante explícito; o draft já a lista entre os invariantes, o que é coerente, mas confirma que D3 é emenda de lei, não elemento.

**D7 — Regra append-only / reducer puro na montagem. Conceito existente: `domainspec-research-writer` ("no synthesis, no editing of child output"; mechanical assembly). Natureza: REFINAMENTO sem ponteiro interno.**
Como em D1, a matriz cita só E2 §LangGraph e a derivação via P10 (E3 R3). O contrato interno já nomeado do research-writer proíbe editar output de filho na montagem — o núcleo da regra existe com dono no repo. O delta genuíno: a semântica de imutabilidade estendida a NOVAS seções (turnos de síntese, rounds) e a cláusula "imóvel ≠ arquivo congelado" — isso o research-writer não cobre, pois ele só monta returns de filhos. *Correção:* citar o research-writer como precedente interno nomeado e declarar o delta como "extensão da imutabilidade do writer às seções de síntese/zig-zag".

**D8 — Draft do synthesizer persistido em research.md. Natureza: NOVO REAL — mas estende silenciosamente a definição P9 de research.md.**
Nenhuma lei existente manda persistir o draft do synthesizer; o elemento é aquisição genuína (a quebra F11 o testemunha). Porém P9 define research.md como "the collected returns" (dos agentes coletados) — colocar nele seções de síntese e turnos de zig-zag **muda a extensão do termo research.md** de "returns coletados" para "returns coletados + camada de síntese append-only". Isso é mudança de definição constitucional feita de passagem numa tabela de edges. *Correção:* declarar explicitamente: "este contrato estende a definição P9 de research.md; alternativa rejeitada: arquivo separado synthesis.md (rejeitada porque a quebra F11 mostra que veredito e alvo precisam do MESMO artefato durável)". Com a declaração, GO limpo.

**D9 — `schema_version` no frontmatter do findings. Conceito existente: campo §5 `schema_version` (nível DISPATCH). Natureza: REFINAMENTO menor sem ponteiro.**
O campo já existe, nomeado, com semântica de grandfathering (§5). O draft propõe espelhá-lo no frontmatter do artefato — delta real (artefato vs registry row), custo zero, mas a linha não cita §5; um leitor pode cunhar semântica divergente para o mesmo nome. *Correção:* "= §5 `schema_version`, espelhado no artefato; mesma semântica, mesmo valor".

**D10 — Exemplar positivo (sem correção).** A linha "Input por role = prosa de briefing" é o modelo do que este gate exige: identifica que o conceito JÁ existe (§5, E3 R8), declara o verdict como NÃO CRESCER e congela. As linhas D1/D2/D7/D9 deveriam ter essa forma. Igualmente correto: o tier de verificação se declara "invenção nossa" — novo real honesto.

## Balanço

15 elementos avaliados na matriz + edges. **Colapso total: 2** (D4 pares P14; D6 Dissent persistida — ambos lei vigente apresentada com verdict GO). **Refinamento genuíno carente de ponteiro ou de declaração de emenda: 5** (D1, D2, D3, D7, D9 — D3 é o mais grave por afrouxar lei sem se declarar emenda). **Novo real: 2** bem declarados (tier; draft do synthesizer — D8 com correção de declaração). O restante da matriz (âncoras de evidência, KILL do schema do corpo, output do reviewer, shape do findings, round condicional) passa o gate: ou não tem conceito interno homônimo, ou o draft já faz a demoção corretamente.

Recomendação estrutural única que resolve D4/D5/D6 de uma vez: introduzir na matriz uma quarta categoria de verdict — **"LEI" (já vigente; o contrato referencia e verifica, não adota)** — e re-rotular; a contagem de aquisições do dispatch cai de ~13 GO para ~9 GO + 2 LEI + 2 NOVO, o que é a contagem honesta sob P10.

Dissent: minha classificação de D6 como colapso total depende de "verbatim" já ser lei vinculante (skill §Outputs) e não guidance — se o skill for lido como guidance até este dispatch promovê-lo, D6 vira refinamento legítimo e o draft está certo; e a categoria "LEI" que proponho pode ela mesma ser inflação de processo se a matriz do skill já admitir leis como linhas não-candidatas.
