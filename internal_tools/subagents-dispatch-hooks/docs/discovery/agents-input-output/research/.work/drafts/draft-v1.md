# findings (draft v1) — dispatch 2026-06-12-agent-io-contracts

## 1. Contexto + Goal

Dois dispatches reais de 2026-06-12 expuseram quebras na cadeia claim→prova (camada de síntese nunca persistida, linhas `Dissent:` ausentes, citações terminando em transcript efêmero), enquanto a constituição v0.5.2 e o type skill `research` exigem que toda claim load-bearing do `findings.md` cite o return coletado que a sustenta (P9). **Goal:** determinar o que os contratos de input/output por role (explorer, synthesizer, reviewer) devem conter para que a citação P9 seja verificável e a síntese não degrade — com base em precedente externo (E2), evidência formal (E3) e prática interna registrada (E1).

## 3. Síntese e tratamento dos dissensos

A convergência central dos três returns é maior do que cada um previu: **o contrato vencedor é envelope estruturado sobre corpo livre, com a verificabilidade morando na persistência e num check de close — nunca em tipar o raciocínio**. E2 mostra que os seis precedentes mantêm exatamente esse equilíbrio (research.md §E2, "Padronizado" 1 e 4); E3 deriva que só campos consumidos por checagens nomeadas sobrevivem (E3 R5 e §Evidência interna); E1 mostra que tudo que quebrou na prática foi persistência seletiva, não falta de estrutura (E1 evidência 2). As três linhas `Dissent:` previram colisões; duas se resolvem por demoção, uma fica aberta:

**Colisão 1 — E1 vs E2: "a concatenação atual já basta" vs "falta o passo dedicado de checagem".** E1 (Dissent) prevê que markdown + namespaces + âncoras já entregam P9 resolúvel e que um schema repetiria o erro v0.3.0; E2 (Dissent) responde que a peça faltante não é formato, é o CitationAgent-equivalente. Os dados de E1 sustentam os dois ao mesmo tempo: toda citação contra return **persistido** resolveu (E1 evidência 1), e toda quebra ocorreu onde nada checava a cadeia no fechamento (E1 evidência 2 — camada F dangling e reviewers no transcript passaram sem detecção). **Resolução por demoção:** adoto a *função* de E2 (checagem de citação como passo explícito do close) na *forma* de E1 (checklist, não agente novo nem schema), alojada onde E3 mostra que ela já mora constitucionalmente — o `final_approver`, que recebe o working_folder completo e cuja aceitação inclui o check P9 (E3 R7, P12). O checklist mínimo: (i) toda citação do findings resolve para texto persistido em research.md; (ii) todo return termina em `Dissent:`; (iii) draft do synthesizer está persistido com IDs; (iv) posições inicial/final presentes se robot-talks rodou; (v) nenhuma cadeia termina em "session transcript".

**Colisão 2 — E2/E1 vs E3: granularidade da âncora (ID por claim vs seção por agente).** E3 R1 sustenta que resolução em nível de seção satisfaz P9 e que IDs por parágrafo são "custo sem regra que a exija". Resolvo CONTRA E3 usando o critério do próprio E3: R5 estabelece que um campo entra no contrato se uma checagem nomeada o lê — e a checagem P9 lê IDs de claim nos dois registros reais ("E2 C1/C2", "F11; E2#1–2"), com custo observado zero, porque os namespaces emergiram duas vezes sem serem exigidos (E1 evidência 1). O custo que E3 teme (estrutura imposta degradando raciocínio) não se aplica: o ID é pós-raciocínio, envelope e não corpo — a própria leitura de E3 da evidência Tam et al. classifica numeração de findings como zona segura (E3 evidência (a), "Leitura para o contrato"). Demovo apenas a força: IDs são **obrigatórios no output do explorer**, mas a citação em nível de seção não invalida um findings — degrada a checagem de mecânica para juízo, o que o approver pode aceitar declarando-o.

**Colisão 3 — E3 vs E1: validação mecânica dos contratos.** E1 (Dissent) rejeita schema executável (as duas quebras reais "seriam pegas por um checklist de 5 itens"); E3 não chegou a propor schema executável — propôs o mínimo derivável —, mas seu critério R5 deixaria um lint de envelope entrar se uma checagem o consumisse, e E2 importa o `CantHandleException` (rejeitar return malformado na entrada do reducer). Não há testemunha interna de return de explorer malformado (as quebras foram de synthesizer/reviewer sub-persistidos), então um rejeitador mecânico não tem caso de uso provado. **Fica ABERTA** a forma do check de coleta: checklist lido pelo strategist na hora do concat (custo zero, sem testemunha contra) vs script (sem testemunha a favor; cheiro de v0.3.0). Registro como dissenso aberto; default operacional enquanto aberto: checklist.

Duas demoções adicionais por P10: (a) o **tier de verificação por claim** é invenção nossa sem dono externo (E2 §Idiossincrático 1) — entra como GO porque a prática o inventou ad-hoc duas vezes sob pressão real (E1 evidências 2 e 6), mas deve ser declarado invenção, não adoção; (b) o **shape literal da matriz de vereditos** do SKILL nunca foi usado (E1 evidência 7) — o contrato deve exigir os invariantes (todo claim cita ID, negativas mortas registradas, tensões abertas não suavizadas, close com exit_reason+agents_spawned), não o shape.

## 4. Contratos por edge

| edge | payload | formato | invariantes |
|---|---|---|---|
| **explorer → research.md** | return integral, verbatim | markdown; header `## E<n> — <nome> (<ângulo>, <modelo>)`; claims com ID em namespace próprio do agente; evidência ancorada (arquivo+linha, seção ou URL); última linha `Dissent:` | montagem = reducer append-only puro (concat sob header, conteúdo do filho congelado, ordem determinística — research.md §E2 LangGraph); checklist de envelope na coleta (header? Dissent? IDs?) → falha = re-ask ao agente, nunca conserto silencioso pelo parent |
| **research.md → synthesizer** | o arquivo research.md completo (returns verbatim) + sob robot-talks os pares posição-inicial/final por reviewer (P14) | referência leve ao arquivo — nunca transcripts de explorer (research.md §E2 Anthropic/OpenAI `input_filter`) | research.md imóvel durante a síntese (E3 R3); synthesizer não recebe nem produz resumo intermediário entre o explorer e a checagem (E3 evidência (b)) |
| **synthesizer ↔ reviewer (zig-zag)** | ida: draft persistido com IDs próprios (`F*`) em research.md/.work ANTES da revisão; volta: veredito por ID alheio (`UPHELD/REFUTED/downgrade` + razão de 1 linha) + claims novos em namespace próprio (`N*`) carimbados `not-re-reviewed` + posições inicial E final | markdown append-only no research.md, uma seção por turno | nenhum turno absorvido pelo parent sem deviation declarada (E1 evidência 2); claim do draft nunca citável apenas via veredito do reviewer (a quebra F11); "full text is in the session transcript" proibido como destino de cadeia |
| **synthesizer → explorers (feedback)** | feedback-prompt verbatim + asks específicos por ID de claim | novo round = nova seção `(round N)` append-only; prompt gravado na close row (P3) | returns já citados são imutáveis (E3 R3); `round` só é marcado quando este edge dispara (E3 R2) |
| **close** | findings.md: matriz de vereditos (ou shape equivalente preservando os invariantes), toda claim citando ID, tier de verificação por claim, resposta de 1 linha ao goal; frontmatter com `dispatch_id` + `schema_version` + exit_reason + agents_spawned + desvios | markdown | approver recebe o working_folder COMPLETO, nunca digest (P12, E3 evidência (b)); aceitação = checklist P9 dos 5 itens (§3, colisão 1); KILLs banked como negativas tipadas para não serem re-levantadas |

## 5. Resposta de uma linha ao goal

Os contratos por role são envelope estruturado sobre corpo livre — header identidade+ângulo+modelo, IDs de claim com namespace por agente, âncoras de evidência, linha `Dissent:` persistida no explorer; draft persistido com IDs próprios antes da revisão no synthesizer; veredito por ID alheio com tier de verificação e posições inicial/final no reviewer — montados por concat append-only verbatim (com invariantes declarados se condensar) e fechados por um checklist P9 explícito do approver; tipar o corpo epistêmico é KILL unânime.
