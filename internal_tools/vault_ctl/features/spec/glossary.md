# Glossary: vault_ctl

Quick-reference glossary for the validator/edge-linter/snapshotter vocabulary. Authoritative behavior lives in [SPEC.md](SPEC.md) and the linked source documents; this file is the readable distillation.

## Feature Language

| Term | Meaning in this feature | Related Concepts |
| ---- | ----------------------- | ---------------- |
| **Rule vs. Discipline** | A **rule** is a constraint a machine refuses to violate; a **discipline** is a constraint a human or agent tries to honor. `vault_ctl` exists to convert vault metadata rules from the second kind to the first. | [documents-metadata-enforcement §2](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#rule-vs-discipline); user memory `feedback_epistemic_honesty.md` |
| **Validation tier** | Cost-of-detection bucket for a check. **Tier 1** = local frontmatter (each file self-validates; cheapest). **Tier 2** = local edge-name + catalog membership. **Tier 3** = graph-global (requires loading every vault file; only this tier closes the bidirectionality gap). | [documents-metadata-enforcement §2](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#validation-tiers) |
| **Enforcement surface** | A single named place where rules run. `vault_ctl` is the **A-3 CLI** building block; the pre-commit hook (A-1) runs Tier 1+2 and CI (A-2) runs Tier 1+2+3 against it. | [documents-metadata-enforcement §4-§5](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#4-enforcement-surface-alternatives) |
| **Carve-out** | An exception to the bidirectionality audit. Two exist: **skill/agent-target** (edges into `.claude/skills/**` and `.claude/agents/**` are forward-only by design and require no inverse); **session-source** (edges whose source has `is_session: true` are forward-only by source). The auditor MUST skip both. | [conventions §8 Carve-out](../../../../vault/ontology-conventions.md#edge-types-connections-section), [kernel R-Edge-Skill-Carveout / R-Edge-Session-Carveout](../../../vault_common/features/spec/SPEC.md#extractedges) |
| **Three sinks** | The three high-traffic vault files that carry no `## Connections` block today: `vault/ontology-conventions.md`, `vault/confidence-levels.md`, `vault/ontology-architecture-draft.md`. Every inbound edge to them is a missing inverse by definition. `lint-edges` Tier 1 bootstraps them. | [inverse-edge-fix §2.3](../../../../vault/discovery/inverse-edge-fix/inverse-edge-fix.md#23-the-three-sinks-problem) |
| **Snapshot zero** | The first content-addressed manifest of `vault/**`, tagged `vault-corpus-v0`. Day-1 artifact per D-2; hand-writeable if the CLI is not ready; the single highest-leverage artifact in the platform plan because the 30-day residue clock does not pause for tooling. | [platform D-2](../../../../vault/discovery/two-layer-platform-architecture/discovery.md#d-2-vault_ctl-is-foundational-snapshot-zero-on-day-1), [D-7](../../../../vault/discovery/two-layer-platform-architecture/discovery.md#d-7-stable-test-corpus-is-non-negotiable) |
| **Stable test corpus** | The vault snapshot every subsystem reads against by default. Pinned to `vault-corpus-v0` (the snapshot zero tag); falsifiability of EVōC convergence depends on it. | [platform D-7](../../../../vault/discovery/two-layer-platform-architecture/discovery.md#d-7-stable-test-corpus-is-non-negotiable) |
| **Cleanup ramp** | The advisory-then-enforcing rollout: validator ships emitting findings; `--strict-all` (Tier 3 gating in CI) flips on only after the known violations are cleaned up. Deadline owned by user, not by spec. | [documents-metadata-enforcement OQ-3](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#oq-3--how-should-the-linter-handle-pre-existing-non-conformant-documents-during-rollout) |
| **Kernel debt** | A `vault_ctl` capability blocked on an unresolved kernel open question (OQ-A, OQ-B, OQ-E, OQ-G). The spec is written against the kernel SPEC contract, so capabilities mark their kernel-debt explicitly and the implementation work-pack gates on the kernel patch. | [kernel SPEC §Open Questions](../../../vault_common/features/spec/SPEC.md#open-questions) |
| **Rescope** | The D-5 reshaping of `vault_ctl`: promotion/demotion moves to `vault_telemetry`; session-close stays in the `close-session` skill; catalog amendment goes to `domainspec-vault-edges/`. What remains: `validate`, `lint-edges`, `snapshot`. | [platform D-5](../../../../vault/discovery/two-layer-platform-architecture/discovery.md#d-5-re-scope-vault_ctl-absorb-promotiondemotion-into-vault_telemetry-route-session-close-to-the-existing-skill) |

## Terms

| Term | Concept ID | Type | Definition | Source |
| ---- | ---------- | ---- | ---------- | ------ |
| **ValidateFrontmatterTier1** | `vault_ctl.ValidateFrontmatterTier1` | Capability | Per-file frontmatter completeness, enum-value, and conditional-confidence validation. Closes failure modes F7, F8, F10. Pre-commit + CI surfaces. | [SPEC §ValidateFrontmatterTier1](SPEC.md#validatefrontmattertier1) |
| **ValidateEdgeCatalogTier2** | `vault_ctl.ValidateEdgeCatalogTier2` | Capability | Per-file edge-name validity against the 21-edge catalog + deprecated-edge detection. Closes F4, F5. | [SPEC §ValidateEdgeCatalogTier2](SPEC.md#validateedgecatalogtier2) |
| **ValidateGraphTier3** | `vault_ctl.ValidateGraphTier3` | Capability | Cross-file audits: missing-inverse (with carve-outs), dangling targets, endpoint cardinality per Appendix C, symmetric `contradicts`. Closes F1, F2, F3, F6, F9. CI surface only. | [SPEC §ValidateGraphTier3](SPEC.md#validategraphtier3) |
| **LintEdgesTier1Bootstrap** | `vault_ctl.LintEdgesTier1Bootstrap` | Capability | Append canonical `## Connections` table header (header only, no rows) to each of the THREE_SINKS. Idempotent. | [SPEC §LintEdgesTier1Bootstrap](SPEC.md#lintedgestier1bootstrap) |
| **LintEdgesTier2InsertInverses** | `vault_ctl.LintEdgesTier2InsertInverses` | Capability | Insert the ~90 reciprocal rows on vault-internal targets for forward edges where forward+inverse are uncontested catalog names. Idempotent; honors carve-outs. | [SPEC §LintEdgesTier2InsertInverses](SPEC.md#lintedgestier2insertinverses) |
| **LintEdgesTier3Report** | `vault_ctl.LintEdgesTier3Report` | Capability | Read-only enumeration of rows blocked on upstream catalog/dangling work. Each row carries a `suggested_workstream` pointer. | [SPEC §LintEdgesTier3Report](SPEC.md#lintedgestier3report) |
| **Snapshot** | `vault_ctl.Snapshot` | Capability | Walk vault, build a content-addressed `Manifest`, atomic write to `vault/snapshots/<date>-<tag>.json`. First invocation tagged `vault-corpus-v0`. Hand-writeable. | [SPEC §Snapshot](SPEC.md#snapshot) |
| **EmitValidationEvents** | `vault_ctl.EmitValidationEvents` | Capability | Append-only event stream over kernel `EventSink`; six `EventKind` values. The only cross-subsystem seam. | [SPEC §EmitValidationEvents](SPEC.md#emitvalidationevents) |
| **Finding** | `vault_ctl.Finding` | Value Object | Immutable `(path, tier, code, message, source_loc)`. The atom of validator output. Codes use the `V-T<tier>-F<n>` namespace for discovery-numbered modes; `V-T<tier>-X<n>` for spec extensions. | [SPEC §Domain Concepts](SPEC.md#domain-concepts) |
| **Tier** | `vault_ctl.Tier` | Enum | `1` (frontmatter-local), `2` (edge-syntax-local), `3` (graph-global). | [SPEC §Domain Concepts](SPEC.md#domain-concepts), [documents-metadata-enforcement §2](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#validation-tiers) |
| **MissingInverseReport** | `vault_ctl.MissingInverseReport` | Value Object | List of `(src, dst, edge_type, expected_inverse, target_has_connections_block)`. The Tier-3 F1 output; the input from which `LintEdgesTier2InsertInverses` derives candidates. | [SPEC §ValidateGraphTier3](SPEC.md#validategraphtier3) |
| **DanglingTargetReport** | `vault_ctl.DanglingTargetReport` | Value Object | Edges whose `dst` does not resolve to an existing file or to a valid carve-out path. Tier-3 F3 output. | [SPEC §ValidateGraphTier3](SPEC.md#validategraphtier3) |
| **EndpointMismatchReport** | `vault_ctl.EndpointMismatchReport` | Value Object | Edges whose `(src.node_type, dst.node_type)` violates conventions Appendix C cardinality. Tier-3 F6 output. | [SPEC §ValidateGraphTier3](SPEC.md#validategraphtier3) |
| **ContradictsAsymmetryReport** | `vault_ctl.ContradictsAsymmetryReport` | Value Object | One-sided or wrong-verb `contradicts` declarations. Tier-3 F9 output. | [SPEC §ValidateGraphTier3](SPEC.md#validategraphtier3) |
| **InverseCandidate** | `vault_ctl.InverseCandidate` | Value Object | `(source_path, target_path, forward_verb, inverse_verb, source_loc)`. A row eligible for Tier-2 mechanical insert — only built when all four §3.2 preconditions hold. | [SPEC §LintEdgesTier2InsertInverses](SPEC.md#lintedgestier2insertinverses), [inverse-edge-fix §3.2](../../../../vault/discovery/inverse-edge-fix/inverse-edge-fix.md#32-tier-2--low-risk-inverse-additions-mechanical) |
| **BlockedReason** | `vault_ctl.BlockedReason` | Enum | `off-catalog-forward`, `contested-inverse`, `dangling-target`, `target-without-connections-block`, `endpoint-cardinality-violation`. Each row in `Tier3Report` carries one. | [SPEC §LintEdgesTier3Report](SPEC.md#lintedgestier3report) |
| **Manifest** | `vault_ctl.Manifest` | Value Object | `{schema_version, tag, created_at, description, file_count, corpus_hash, entries}`. The snapshot's serialized form. Hand-writeable in JSON per R-S-Hand-Writeable. | [SPEC §Snapshot](SPEC.md#snapshot) |
| **ManifestEntry** | `vault_ctl.ManifestEntry` | Value Object | `(relative_path, sha256, mtime, frontmatter_node_type, schema_version)`. One per non-excluded `vault/**` file. | [SPEC §Snapshot](SPEC.md#snapshot) |
| **MANIFEST_SCHEMA_VERSION** | `vault_ctl.MANIFEST_SCHEMA_VERSION` | Int | The integer that names the manifest's structural version. Currently `1` for this spec; the on-disk format is `0`. Bumps require a backward-compat reader (SPEC OQ-9). | [SPEC §Snapshot](SPEC.md#snapshot) |
| **THREE_SINKS** | `vault_ctl.THREE_SINKS` | Frozenset[Path] | The three high-traffic vault sinks bootstrapped by `LintEdgesTier1Bootstrap`: `vault/ontology-conventions.md`, `vault/confidence-levels.md`, `vault/ontology-architecture-draft.md`. | [SPEC §LintEdgesTier1Bootstrap](SPEC.md#lintedgestier1bootstrap), [inverse-edge-fix §3.1](../../../../vault/discovery/inverse-edge-fix/inverse-edge-fix.md#31-tier-1--bootstrap-the-three-high-traffic-sinks-low-risk-high-leverage) |
| **DEPRECATED_EDGES** | `vault_ctl.DEPRECATED_EDGES` | Frozenset[str] | The retired edge verbs from conventions Appendix C: `resolves`, `references`, `contextualizes`, `exemplifies`, `depends-on`, `questions`, `updates`, `deprecates`, `produces`, `produced-by`, `provenance-for`, `grounds`, `grounded-by`. Source of F5 detection. | [SPEC §ValidateEdgeCatalogTier2](SPEC.md#validateedgecatalogtier2), [conventions "Edges deprecated"](../../../../vault/ontology-conventions.md#edges-deprecated-by-this-catalog) |
| **EventKind** | `vault_ctl.EventKind` | Enum | The six event verbs `vault_ctl` may emit: `validation.failed`, `validation.completed`, `edges.lint.bootstrapped`, `edges.lint.inserted`, `edges.lint.reported`, `snapshot.taken`. Each has a documented payload contract. | [SPEC §EmitValidationEvents](SPEC.md#emitvalidationevents) |
| **F1–F10** | (discovery-numbered codes) | Failure-mode taxonomy | The ten failure modes the discipline gap admits. F1 = missing inverse; F2 = asymmetric pair; F3 = broken target; F4 = invalid edge name; F5 = deprecated edge; F6 = endpoint type mismatch; F7 = missing required frontmatter; F8 = forbidden conditional field; F9 = asymmetric `contradicts`; F10 = frontmatter not on line 1. | [documents-metadata-enforcement §3](../../../../vault/discovery/documents-metadata-enforcement/documents-metadata-enforcement.md#3-failure-modes-the-discipline-gap-admits) |

## Maintenance Rules

- Use **Feature Language** rows for `vault_ctl`-internal terms a reader needs before formal concept rows make sense (Rule vs. Discipline, Validation tier, Enforcement surface, Carve-out, Three sinks, Snapshot zero, Stable test corpus, Cleanup ramp, Kernel debt, Rescope).
- Derive formal concept rows from [SPEC.md Concept Registry](SPEC.md#concept-registry); any new entry there requires a row here.
- Keep each definition to a single domain-level sentence that *teaches* the term rather than restating the SPEC table.
- Every link MUST resolve to its authoritative source anchor — `vault_ctl` SPEC, kernel SPEC, conventions, constitution, or source discovery.
- When a `vault_ctl` `R-*` rule changes or a concept name changes, update this glossary in the same PR as the SPEC change.
- Do not introduce new canonical behavior here; update the SPEC or the upstream conventions/constitution/discovery first.
- When `vault_telemetry`'s own spec lands, replace the textual Cross-Feature row with a link to that spec.
