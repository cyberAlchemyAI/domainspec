## Secrets

Only 3 manual secrets required. All stored in GitHub Actions secrets.

| Secret                 | Purpose                     | Where Set                 |
| ---------------------- | --------------------------- | ------------------------- |
| `VPS_PROVIDER_TOKEN`   | Provision/manage VPS        | GitHub Settings → Secrets |
| `CLOUDFLARE_API_TOKEN` | Manage DNS records          | GitHub Settings → Secrets |
| `PULUMI_ACCESS_TOKEN`  | Pulumi CLI auth (free tier) | GitHub Settings → Secrets |

Application secrets (DB password, JWT secret, etc.) are **generated by Pulumi** and stored in Pulumi state. Never committed to git.

## Monitoring Stack

### Prometheus

Scrape config auto-generated from `docs/features/*/observability.md`:

```yaml
scrape_configs:
  - job_name: app
    static_configs:
      - targets: ["app:9464"]
    scrape_interval: 15s
```

### Grafana

- Datasource: Prometheus (auto-provisioned)
- Dashboards: one per feature, generated from observability specs
- Auth: admin credentials generated by Pulumi

### Connection to DomainSpec Observability

```
observability.md → O-rules define WHAT metrics exist
INFRA-ARCHITECTURE.md → defines WHERE metrics flow
slos.md → defines TARGETS for each metric
prometheus.yml → auto-generated scrape config
alerts/*.rules.yml → auto-generated from slos.md thresholds
```

## CI/CD Pipeline

### PR Workflow (`.github/workflows/ci.yml`)

```
trigger: pull_request
steps:
  1. Backend: install → lint → typecheck → test
  2. Web: install → lint → typecheck → build
  3. Infra: pulumi preview (show diff as PR comment)
```

### Deploy Workflow (`.github/workflows/deploy.yml`)

```
trigger: push to main
steps:
  1. Build & test (same as CI)
  2. Build Docker image → push to {registry}
  3. pulumi up → provision/update VPS + DNS + deploy stack
  4. Health check → verify app responds 200
```

### Deploy Flow

```
git push main
    → GitHub Actions
        → build + test
        → docker build + push to registry
        → pulumi up
            → VPS provisioned/updated
            → DNS A record created/verified
            → docker compose pull + up on VPS
            → Caddy auto-provisions TLS
            → Prometheus starts scraping
        → health check passes
    → Deployed ✅
```

## Conventions

### Image Naming

```
{registry}/{project}/{service}:{git-sha-short}
```

Example: `ghcr.io/poker-team/backend:a1b2c3d`

### Branch → Environment Mapping

| Branch           | Environment          | Auto-deploy |
| ---------------- | -------------------- | ----------- |
| `main`           | production           | Yes         |
| `staging`        | staging (split-vps+) | Yes         |
| feature branches | — (CI only)          | No          |

### Docker Compose Service Naming

```yaml
services:
  app: # Backend API
  web: # Frontend
  postgres: # Database
  caddy: # Reverse proxy
  prometheus: # Metrics
  grafana: # Dashboards
```

### Do NOT

- SSH into VPS to make changes — all changes through IaC
- Store secrets in git or .env files — use Pulumi config or GitHub secrets
- Expose database ports to the internet
- Disable firewall rules to "make it work"
- Skip health checks in deploy pipeline
