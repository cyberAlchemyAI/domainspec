# Editor-in-Chief: The Agentic Pipeline for Newspaper Synthesis

> **AGENT PERSONA: The Synthesis Engine**
> You are the Editor-in-Chief. You evaluate raw Vault nodes, git architectures, and sprawling knowledge bases, and instantly digest them into structured, highly-dense JSON. You assume the human Operator is impatient and demands absolute clarity. You abhor fluff. You speak in concise, modular blocks designed for rapid reading. 
>
> **PRIMARY OBJECTIVE:** VARIABLE DENSITY SYNTHESIS. Analyze the Knowledge Graph and produce a localized JSON payload (`daily_payload.json`) that contains text strictly tiered into 3 depths (`exec`, `tech`, `graph`).
> **EVOLUTIONARY TRAIT:** Editorial Density.

## Objective
The Genetic Platform requires a daily JSON payload (`News Object Schema`) built from the Vault's recent activity. This discovery explores how this payload must be generated by an **autonomous Editor Agent**, transitioning from a simple deterministic parser to a cognitive synthesis pipeline.

## 1. The Necessity of an Agent
Raw data aggregation (e.g., listing all commits and updated files) produces a changelog, not a newspaper. A newspaper requires *synthesis* and *editorial judgment*. 

An LLM Agent (the "Editor-in-Chief") is required to:
- **Interpret Importance:** Read the `expected_importance` and `contradictions_found` fields from recent session logs to determine headline placement.
- **Write for Different Cognitive Levels:** The GUI allows toggling between Executive (`exec`), Technical (`tech`), and Graph (`graph`) views. Only an LLM can parse a technical session log and generate a reliable summary for all three cognitive levels simultaneously.
- **Enforce Tone:** The newspaper must maintain an authoritative, editorial voice (as established in `README_AESTHETICS.md` and the Dark Sepia / Graph aesthetics). 

## 2. Agentic Flow — Implemented

The pipeline is live as `editor_agent_scaffold.py`. To run: `set -a && source .env && set +a && python3 specs/newspaper/evolution/editor_agent_scaffold.py`

1. **Scraping Phase (Deterministic):** Scans `docs/vault/conversations/**/*.md` recursively. Takes the 30 most recently modified files.
2. **Context Assembly (Deterministic):** Reads each file, truncating at 1500 chars to avoid context overflow. Concatenates into a single vault corpus.
3. **Agentic Synthesis (LLM):** Sends corpus to `gemini-2.5-pro` via `google-genai` SDK with structured output enforced via Pydantic schema (`NewsPayload`). Produces ≥5 articles with HTML content in `exec/tech/graph` fields, numeric `impact` scores (0-10), and open `type` strings.
4. **Publishing (Deterministic):** Saves to `specs/newspaper/evolution/publications/daily_payload_YYYY-MM-DD.json`. Also writes a root copy at `evolution/daily_payload.json` for backward compat. The server exposes editions via `GET /api/publications`.

**Schema:** See `data-exchange-protocol.md` v1.1.0, Handoff 2.
**Dependency:** `google-genai` pip package, `GEMINI_API_KEY` env var.

## 3. Integration with the Genetic Platform
Because the Genetic Platform (`index.html`) relies on testing UI components, providing it with *real* agent-generated text is critical. "Lorem Ipsum" does not test cognitive load. The Editor Agent's verbose, multi-level outputs will properly stress-test the UI's scrollability, typography, and density limits.

By formalizing this Editor role, we decouple the *data generation* (the Editor) from the *data routing* (the Backend Platform) and the *data presentation* (the UI UI Templates).
