# Glossary: UI Prototyping Studio

Quick-reference glossary of UI Prototyping Studio language and concepts distilled from the feature specification and aspect documents.

Scope note: This glossary explains what feature terms mean in ordinary product language first, then links each formal concept back to its authoritative source. Authoritative behavior, fields, rules, and lifecycle contracts remain in the linked source documents.

## Feature Language

These are the words a reader needs before the formal concept table makes sense.

| Term       | Meaning in this feature                                                                                                                                                                                                                                                      | Related Concepts                                                                                                                                                                |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Baseline   | The prototype version the team has chosen as the current reference point for comments, generated change tasks, approval, revisions, and handoff. In a three-option run, the user selects it; in a one-option run, the only variant is automatically treated as the baseline. | [BaselineProvenance](domain.md#baselineprovenance), [BaselineMode](domain.md#baselinemode), [SelectOrCommitBaseline](operations.md#selectorcommitbaseline)                      |
| Variant    | One candidate prototype option generated from the prompt. Variants are compared before a baseline is selected or committed.                                                                                                                                                  | [PrototypeVariant](domain.md#prototypevariant), [VariantCount](domain.md#variantcount), [GenerateVariants](operations.md#generatevariants)                                      |
| Gate       | A checkpoint that blocks the workflow until required human or rule-based conditions are satisfied. The studio uses gates to prevent comments, task synthesis, or apply actions from running too early.                                                                       | [GateState](domain.md#gatestate), [GovernanceGatePolicy](workflows.md#governancegatepolicy)                                                                                     |
| Revision   | A recorded version of the prototype after an approved batch has been applied. Revisions provide the traceable history used for resume and handoff.                                                                                                                           | [RevisionManifestEntry](domain.md#revisionmanifestentry), [ListRevisionManifest](queries.md#listrevisionmanifest)                                                               |
| Mutation   | A proposed change to the active baseline. Mutations are grouped into a batch, reviewed, approved, then applied manually.                                                                                                                                                     | [MutationTask](domain.md#mutationtask), [MutationBatch](domain.md#mutationbatch), [ApplyApprovedBatch](operations.md#applyapprovedbatch)                                        |
| Genome     | The encoded instruction set that shapes the next prototype generation: prompt hash, component constraints, environment references, comments, and mutation tasks.                                                                                                             | [PrototypeGenome](domain.md#prototypegenome), [EvolutionCycle](domain.md#evolutioncycle)                                                                                        |
| Fitness    | Selection pressure that explains why a variant, mutation, or revision should survive, change, or be blocked.                                                                                                                                                                 | [FitnessSignal](domain.md#fitnesssignal), [FitnessVector](domain.md#fitnessvector), [RecordFitnessSignal](operations.md#recordfitnesssignal)                                    |
| Lineage    | The ancestry of selected baselines, approved mutations, and recorded revisions that shows how the interface evolved over time.                                                                                                                                               | [EvolutionCycle](domain.md#evolutioncycle), [RevisionManifestEntry](domain.md#revisionmanifestentry), [GodelDarwinEvolutionWorkflow](workflows.md#godeldarwinevolutionworkflow) |
| Proof Gate | The Godel side of the studio: durable mutation or self-improvement is allowed only when explicit obligations have passable evidence.                                                                                                                                         | [ProofObligation](domain.md#proofobligation), [EvaluateProofGate](operations.md#evaluateproofgate), [GodelProofGatePolicy](workflows.md#godelproofgatepolicy)                   |
| Handoff    | The exportable evidence bundle that tells downstream UI, test, and implementation stages what was decided and where the supporting contracts live.                                                                                                                           | [GetHandoffBundle](queries.md#gethandoffbundle), [ExportDesignHandoff](operations.md#exportdesignhandoff), [IntegrationReadiness](domain.md#integrationreadiness)               |

## Maintenance Rules

- Use Feature Language for important words that appear inside formal concepts, especially when the word is not obvious outside this feature.
- Derive formal concept rows from [SPEC.md](SPEC.md) Concept Registry and aspect-level registries such as [UI-SPEC.md](UI-SPEC.md#ui-concept-registry).
- Keep each formal concept definition to one domain-level sentence, but make the sentence teach the term rather than repeat the source table.
- Link every entry to the authoritative source anchor.
- Update this glossary whenever concept names, concept IDs, source anchors, or definitions change.
- Do not introduce new canonical behavior here; update the source aspect document first.
