## Architecture Constraints Baseline

1. Domain layer keeps entities, rules, policies, and state transitions framework-agnostic.
2. Application layer owns operation/query/workflow orchestration and depends only on domain contracts.
3. Interface/adapters layer owns HTTP parsing, DTO validation, and module contract boundaries.
4. Infrastructure adapters implement domain ports and stay behind application contracts.
5. UI surfaces follow `docs/UI-ARCHITECTURE.md` and must not embed domain/business logic.
6. Self-improvement and generation-rule promotion remain proof-gated and deferred until implementation-layering promotion evidence exists.
